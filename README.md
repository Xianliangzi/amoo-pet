# Amoo Desktop P0

当前版本：六种视频素材、单宠物身份、文字指令、动作引擎、事件记录、规则型长期记忆及 IndexedDB 持久化。

## 本地运行

```powershell
npm install
npm run dev
```

固定访问 http://127.0.0.1:5173 。不要在 localhost 与 127.0.0.1 之间切换，它们的浏览器存储彼此独立。

```powershell
npm run build
```

首次输入名字创建 Amoo。档案写入成功后才显示已保存。刷新或关闭后重新打开同一地址，可以恢复 petId、名字、生日和状态。离线不计算数值变化；页面隐藏期间同样暂停。

文字模拟器支持：喂它、陪它玩、睡觉、醒来、游动、开心、它怎么样。界面仅模拟未来手机纯文字命令与硬件反馈，正式手机端不需要网页 UI。

Pet Engine 统一修改状态并保存，再通过 Device Adapter 显示动画。吃饭、玩耍、开心结束后回待机；睡眠保持循环。睡眠中互动先唤醒，900ms 后执行。刷新遇到未结束的单次动作时回到待机，不重复增加奖励。睡眠及游动可跨刷新保留。

素材预览按钮只切换视频，不触发宠物行为或修改状态；发送指令会自动返回设备模拟。当前动作允许被后续指令打断，不排队。每次写入期间禁止重复提交。

## 文件

- `src/pet.ts`：类型、Dexie repository、Zustand store。
- `src/engine.ts`：规则指令解析、Pet Engine、Device Adapter。
- `src/memory.ts`：事件与记忆类型、首次互动里程碑、陪玩时段偏好规则。
- `src/sensors.ts`：SensorAdapter 与虚拟光线、距离读数。
- `src/App.tsx`：创建、身份与状态调试、六种视频预览。
- `public/amoo/`：用户原片的项目副本，无损复制。
- `docs/progress.md`：范围与验收记录。
- `docs/AMOO_CODEX_HANDOFF.md`：完整产品策划案，含概念定义、数据结构、引擎规则、视觉规范、已购硬件清单与未来方向。换人接手时先读这一份。
- `docs/video-source-map.md`：视频素材溯源与命名映射。

本地数据不跨浏览器同步，清除网站数据会删除档案。尚无云端、LLM、硬件或账户系统。

## 事件与长期记忆

动作会记录事件；创建、命名、首次喂食及首次陪玩产生里程碑。最近 7 次陪玩中至少 5 次落在同一北京时间时段时形成偏好（00–06、06–12、12–18、18–24）。同类记忆去重；已形成的偏好作为历史观察保留，满足同一规则时更新描述，不宣称永久习惯。

输入“你记得什么”可读取记忆，不修改状态、不唤醒睡眠中的宠物。页面提供长期记忆与最近 30 条事件面板。事件、状态、记忆作为同一 IndexedDB 记录原子保存；聊天内容不保存。

数据库 v2 自动升级旧档案，保留身份与状态，仅根据已存储的名字和生日补齐创建、命名事实，不补造历史互动。

## 在线变化与虚拟传感器

每个页面可见的在线分钟：饱腹度 −1；清醒精力 −1，睡眠精力 +3。待机 / 游动每分钟交替；清醒精力降至 15 或以下时自动睡眠。单次动作期间不强行打断，动作结束时检查低精力。精力恢复至 100 后仍保持睡眠，需指令唤醒。后台隐藏、关闭和离线均不追算时间；恢复可见后重新计一分钟。忙碌期间跳过该次 tick，不补算。

调试面板可选择光线（暗 / 正常 / 明亮）与距离（远 / 近），也可手动模拟一个在线分钟：

- 切换为暗：入睡；恢复亮度不自动唤醒。
- 从远变近：清醒且非暗环境下播放 happy、亲密度 +1；不唤醒睡眠中的宠物。
- 因没有独立 approach 素材，暂用 happy 表达靠近回应。
- 传感器仅在读数变化时触发；不反复覆盖文字指令。刷新后读数重置为正常 / 远，宠物状态不重置。

所有状态变化仍通过 Pet Engine，原子记录对应事件。虚拟传感器不连接任何真实硬件。当前按一个活动调试页面运行，不支持多页面同时控制。
